Pushes to `main` (and `v*` tags) trigger the **Build and push Docker images**
workflow (`.github/workflows/build-images.yml`).

## What it does

1. Builds `linux/amd64` + `linux/arm64` images for all three apps via a build
   matrix.
2. Validates that the Supabase secrets are set (skipped for the docs image).
3. Publishes to GitHub Container Registry (GHCR):

| Image | Tags |
| --- | --- |
| `ghcr.io/tikloud/dashboard` | `latest`, semver tags, `sha-*` |
| `ghcr.io/tikloud/landing-page` | `latest`, semver tags, `sha-*` |
| `ghcr.io/tikloud/docs` | `latest`, semver tags, `sha-*` |

## Required secrets

The dashboard and landing-page builds require these repo secrets
(Settings → Secrets and variables → Actions). The workflow fails if they are
unset, because empty values produce a broken auth image:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

## Caching

Builds use the GitHub Actions cache (`type=gha`) for both layers and registry
cache to keep image builds fast across pushes.
